# 每次实验前说明意义

2026-10-19用户明确要求：“以后你每次做实验之前，都想一想这个实验的意义。比如你卡常就没有任何学术意义”。本条优先于历史实验队列的泛化研究叙述，不自动中断已运行的有效作业。

新增研究实验启动前，在对应协议首页简短写明：

1. **问题与证据**：要回答什么具体问题，哪些事实支持提问；论文发现、本实验发现和假说分别标注。
2. **有区分力的干预**：改什么、保留什么、最少需要哪些对照；结果能否区分当前竞争解释，或直接检验明确方法的质量／成本收益。
3. **结果用途**：正结果、负结果各会改变什么结论或下一项方法选择；若两种结果都不改变任何行动，不启动该实验。
4. **目标关联**：怎样推进冻结1%多领域Answer F1与端侧部署优势，是否只优化局部常数、重复已知结论或验证代码。
5. **投入与出口**：估计GPU／QA／额外训练与评价成本，预先给出完成边界；不用TEST调参或按成绩删负条件。

导出／重载／数值／算子／设备守卫可作为必需工程准入，明确标注，不当作学术发现或方法收益。修复验证做到足够支撑下一项科学实验即可，不为多收集通过项反复扩张。不从自己刚选的工具路径倒推共同问题，不以编造故事代替证据。无清楚问题、区分能力与结果用途的新实验不启动；这不是要求每项实验向用户重复索取许可，已有授权内自主执行。

用户仍授权结构／容量等论文级改造。先回答哪些架构扩展确有收益、哪些可移除或避免，并用相同任务与部署口径比较；不能仅以参数多、路由少、理论FLOPs小或低TRAIN loss宣布多余。未形成有效证据前不承诺原创／提升。
