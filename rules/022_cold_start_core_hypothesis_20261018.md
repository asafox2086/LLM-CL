# 核心观测与待证假设：少数据下的新LoRA冷启动代价

用户提出：“大部分现有方法会新增一个LoRA，而因为这个LoRA从零开始，数据又受限，反而训不好？这是一个很重要的观测”。应保留为重点研究方向，但明确以下证据层级。

1. **已确认的局部观测：** 当前自研三专家方案，e1从原基座新建，仅11条QA/一步，随后17阶段权重未变；其薄弱不是后来参数覆盖。与已有完整228题初始化控制精确桥接：fresh19.876、仅旧A19.863、完整旧A+B29.263。完整继承差+9.388，图像区间[4.559,14.330]；同目标训练预算，旧自然347条历史计费。该warm控制不是nativeSeq权重，不能拼入主表。
2. **“从零”指增量：** 预训练多模态基座不重置；新LoRA一般B为0、初始有效增量为0。当前方案从基座新建，没有继承已有LoRA的旧适配函数；不能将其描述为随机训练整个模型。
3. **核心假设：** 在轻量、少数据/少更新条件下，新专家冷启动舍弃可迁移旧适配，而预算不足以补回；它可能比共享/继承单LoRA更差。现有初始化对照支持这个局部方向，尚未证明数据规模与冷启动损害之间的交互。
4. **不可扩大：** 没有审计足够原论文及当前实现前，不写“大部分现有方法都新建且都从基座冷启动”。共享式/正则化/全参数方法不必新建LoRA；新建专家也可能继承/合并旧权重。当前结果不能推导所有复杂方法失败、专业知识充分或所有剩余AP缺口都由冷启动造成。
5. **下一项受控研究：** 只改新专家初始化的完整19阶段对照；另用初始化×独特TRAIN量，在匹配优化步数/总曝光下区分少样本与少更新。原1%1313QA正式基线不改变；扩展TRAIN只能作为单列诊断，采样仅TRAIN/固定seed，全部条件预先报告，不用TEST调参。更新：初始化单变量19阶段控制已实现并准入（37CPU机制/28策略/7继承），当前等待两个原完整确认；GPU收益仍待。初始化×数据量交互尚未实现，不能混称完成。

候选论文表述：在本研究的数据受限设置中，直接从预训练基座新建LoRA专家可能损失既有适配器的可迁移功能；相同目标训练预算下，继承完整旧适配器的局部对照优于重新初始化。这提示新增容量的冷启动代价应与灾难性遗忘共同考察。不得删除“本设置／可能／局部对照”等边界，直到完整控制支持更广结论。
