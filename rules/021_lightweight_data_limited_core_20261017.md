# 核心研究背景：轻量模型、数据受限与低内存增长

2026-10-18用户明确评价口径：以领域总Answer F1及最终AP/FWT/BWT评价收益，并同时报告资源代价；不要求每种题型、语言或样本全面提升。细分退化只能用于解释，不能否定已成立的领域整体增益，不把完成细分保护或增加细分报告设为方法有效的前提。保留已取得证据，不据此扩大细分实验；优先验证有意义的整体提升与轻量代价。

最新用户修订（2026-10-17）优先于历史单LoRA措辞。用户原话：“也不是说只能用一个LoRA，但最好内存增加比较小，至少比LoRA方法少”。

1. **研究目标**：在小模型、冻结1%训练1313QA条件下，找出少量数据／少量更新产生的性质，检验这些性质是否导致既有方法退化，再用针对性模块提高Answer F1。不能直接把已知代数现象当成性能退化原因，也不预设LoRA无效。所有结论按问题、实验、结果、证明、改进、效果六栏记录，并保留证伪和局限。
2. **容量约束**：允许多个LoRA；不存在“只能一个”的硬限制。现有单rank8原型是已冻结的一组实验选择，不是未来方法禁令。优先复用／压缩／控制实际常驻容量，避免随任务数无界增加。目标是实际内存增长低于所比较的LoRA类方法；逐个指明比较方法及口径，不保证低于所有LoRA，也不能在未测时声称低于单个SeqFT-LoRA。
3. **内存证据**：同骨干、相同数据/划分/精度/输入与训练设置、相同硬件和明确测量边界下，报告初始常驻与最终常驻、增长、训练峰值；CPU RSS/PSS/USS与GPU allocated/reserved/NVML分别报告。参数、路由器、冻结专家、历史样本/统计量、优化器、临时候选均计入适当口径。阶段TRAIN窗口与评价峰值分开；不同进程的前后占用不能直接相减。低参数量不自动等于低内存。
4. **计算约束**：额外TRAIN前向、训练曝光、耗时和checkpoint存储也计费；不能靠大量重复计算取得分数后只宣传轻量参数。当前完整原型B额外TRAIN前向上限11430题次，明显高于1313目标QA，须报告实际成本与收益，尚不构成轻量优势。不得为改善分数暗中改用全量训练、增加测试驱动筛选或改动冻结划分。
5. **比较与结论**：两模块四组消融互相独立，不能把四组实验误写为四个常驻LoRA。研究原生AnyRes与正式V2公共缩放的结果分别报告，未经同协议控制不能声称击败正式基线。高分、低增长和可解释的退化原因都需实际对照，目标并非已达成结论。
6. **基线持续**：两台服务器的正式基线通过nohup持续后台运行；研究只用新GPU1，新GPU0保留，不抢占基线卡，不重复启动。核验实际PID、日志和可信完成证明，失去意义的结果隔离后在可追溯版本重跑，不热改活动/排队源码。性能探索不能以暂停基线为代价。

7. **预热口径**：内存增长比较须核对窗口前反向/准入历史。当前T02 control额外做过原训练器准入，其他条件没有；相同最终状态也可有不同before和增长。现有值逐PID描述，不据此宣布模块额外耗内存；未来独立比较采用共同预热/恢复规则，不因此热改或中断活动作业。
