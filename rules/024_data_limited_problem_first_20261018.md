# 最新研究优先级：先探明数据受限下的问题，不预设模块数量

2026-10-18最新用户修订，优先于目标和历史文档中的“两模块”固定结构。

用户原话：“问题没找好，先不要分模块来限制自己”；要求研究别人多领域方法为什么有效、具体怎样更新，以及能否用相似但更轻量的更新取得收益，着重考察数据受限为何会使一些基线变差。

1. 暂不预设模块数量、方法载体、专家数量或必须使用LoRA/SVD。已有机制对照继续，不能把两个对照条件误写为两个已定方法模块。先找可复核的性能原因，再决定方法形式。
2. 分开记录作者论文、作者原实现、我们的骨干适配和实际生效干预。CL-MoE延续已有专家并动量合并，OSFT/PaRSP直接更新已有权重；不能将这些基线统称为每任务从零新增LoRA，不能用原冷启动局部对照解释所有方法。
3. 把数据量作为需要控制的自变量。单一1%上的机制开关只给出该设置的作用；数据受限的交互作用需要同任务／同起点／固定更新预算的不同唯一TRAIN数量对照。重复同一条数据增加更新，不等于获得更多独特信息。
4. 同时检查学前／刚学后／后续最终表现，以区分弱习得和后来损伤；训练信息决定机制，TEST不用于选择路线或超参。最终仍按五领域总Answer F1／AP及合法FWT/BWT评价，不要求所有语言和题型同涨。
5. “很多基线会因少数据变差”是当前重点假说，尚未被正式匹配数据量对照普遍证明。OSFT已在本1%正式配置中胜过SeqFT，所有反例和负结果保留。
6. 轻量比较需明确参数／梯度／优化器／历史统计／临时副本／额外计算与实际CPU/GPU内存。稀疏梯度掩码、较少训练坐标或无新增LoRA均不自动意味着较低峰值内存。

冻结源不热改；基线持续nohup；研究实际空闲GPU0/1单流、我们新机最多占3卡；1313TRAIN／19阶段／21454TEST和原始Answer F1不变。新增诊断的子集与额外曝光须独立记录，不改正式主划分。
