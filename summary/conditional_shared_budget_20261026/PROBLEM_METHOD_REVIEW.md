# 固定低秩预算的粗粒度条件适应：研究提议

状态：问题与方法评判稿，未准入、未实现、未读取新QA、未启动模型或评分。不修改既有实验设置、正式主表或旧关闭判决。是否实施由root在读完本提议后决定；不能把本文当作启动授权。

## 事实、缺口与一个可证伪问题

人类最新允许性能略低而完整内存显著更优，要求抽象强方法的功能，以简洁方式实现，也允许针对共同问题设计方法。当前共同结构事实是PAS与CL-MoE都把输入条件适应放进多个A/B专家银行；这不等于已经发现它们共有的功能缺陷，更没有证明路由导致原F1优势。

现有固定源码中，PAS在七类投影逐token用LoRA-A响应能量softmax，混合两个完整r128专家；并非QA聚类，也没有独立MLP router可以直接删除。CL-MoE在七位置使用八个r8专家（总rank64）、逐token线性router；推理又以冻结语言模型的问题末token特征选最近任务质心，将任务专家权重与token权重各混合一半。原型不是本提议的新发明。PAS另有重要性约束，CL另有阶段统计、额外当前TRAIN前向及动量处理。

PAS专家A/B为140,771,328坐标，CL专家A/B为35,192,832坐标；q/v-r8只有540,672坐标、48个投影。位置、容量、正则、训练曝光和数值实现均不同。因此不从正式PAS高分推断精细路由有效，也不把旧全共享LoRA分数直接当成分组反证。

唯一问题：**在同一q/v-r8总预算与训练曝光下，共享更新加两个很小的条件更新，能否用整题粗硬分工取得足够回答质量，从而省去多完整专家和逐token分配？** 目标是检验这个较简单的功能替代，不证明所有专家都无用，不研究遗忘，也不复活旧FFN响应调制、ShortFixed、量化或其它关闭点。

## 固定容量与初始功能

在原OneVision语言q/v的48个投影中，每个投影把r8拆为共享r4和两个私有r2：

`y = W0 x + 4 B_s A_s x + 4 sum_g w_g B_g A_g x`，`g in {1,2}`。

所有A/B总坐标仍为540,672；A沿原r8初始化分成连续4/2/2行，B分成对应列且全部为零。非共享两臂的A/B形状和初始字节相同，尺度统一为原alpha/r=4，不因活跃rank变化补倍数。全部臂初始实际回答函数为W0，初始化本身不增加有效功能；从首个更新起轨迹可以不同。

最小表示仍保留每投影一张完整r8 A及B、共96个参数对象，4/2/2只是视图切片，避免无故改变optimizer参数对象及step计数。未选私有部分没有本QA的直接损失梯度，但原AdamW动量或weight decay仍可能改变它，不能称未选组参数绝对冻结；不另加冻结/清moment策略。soft/hard使用相同的这一更新合同，真实组曝光与参数变化分开解释。

硬分配每QA只激活一个私有r2，故训练时活跃适应rank为6；软分配激活全部r8。必须披露这一差异。硬分配不能以“存了r8”冒充每QA都使用r8；软/硬差异也不只是一项router参数的有无。

不新建每task专家、不增加rank、不增加学习的分组器。两组容量从开始固定，不依据DEV/TEST或模型正确率增删组。

## 两组如何严格在线形成

先控制表征，使用CL现有语义：只输入原问题文本，沿原分词及至多512 token策略，以**原冻结W0、全部adapter关闭、eval/no_grad**得到最后问题token隐状态。没有图像、答案、task标签、域标签或额外encoder；不是读取完整QA的gold后决定分组。特征提取是一次额外语言前向，不能称0 decoder或免费预处理。

按既定19任务、任务内原训练顺序处理。只在当前task成为合法可访问数据后提取其问题特征；不预读后续task。可为当前task保存一次特征及分配，供原训练曝光消费，不增加有梯度QA、epoch或optimizer更新。特征缓存大小和计算另记；任何重复提取也计费。

两组使用同一确定的在线二质心规则，不引入额外调参：

1. 第一个问题特征作为组1的首样本；首次遇到与其不完全相同的后续特征时建立组2，并将该题分给组2。此前只有组1可选。不从整个S1寻找最远点，不扫描未来阶段找种子。
2. 两组均建立后，每题先用已有两个质心的欧氏距离选最近组，精确平局固定选组1；再把该特征加入所选组的运行和/计数，更新均值。该QA训练使用此已封分配，不能随loss或gold重新分配。
3. 质心跨task继续在线更新，不在task边界重置。因此它不是拿S1自然原型永久代表五域。分组仍可能受早期种子及课程顺序影响；这是本固定简化的局限，不能由算法名字消除。
4. 不作强制均衡、空簇重播种、中心交换、专家复制或按结果救回。若一组不被选择或从未建立，原样报告该退化；不能据此临时重设规则。
5. 评价时冻结当时已由合法TRAIN形成的质心。每个新问题独立提取同一个W0特征、按最近质心选择，不更新中心，不取真实taskID，不用测试batch分布适应。逐task刚习得读数只使用截至当时的中心及参数。

运行和/计数只是训练统计，最终推理只需两个已形成的FP32中心与有效组标志。分组数、中心更新、选择次数用于描述真实干预和退化，不把聚类轮廓或负载均衡当F1收益。

## 最小三臂与识别边界

| 臂 | 适应和分配 | 它回答什么 |
|---|---|---|
| Shared-r8 | 原连续共享q/v-r8；全部8个rank始终参与 | 不分工是否已足够；容量和普通学习锚 |
| Same-bank soft | 同shared4/private2×2；每个投影、每个token以私有A响应平方均值算两分数，固定温度1 softmax；共享分支恒开 | 相同小银行中保留细粒度、随已学A变化的软条件分配 |
| Coarse hard | 同一银行；整QA固定选择一个私有r2，所有位置共用选择；共享分支恒开 | 更粗、无学习router的分工是否已够用 |

soft采用PAS式A响应分数，A本身学习，但没有额外router矩阵、训练坐标或teacher。它是同预算的功能参照，不称原PAS复现；不继承PAS重要性保护、CL动量等历史机制。只比较这一项条件适应问题。

三臂使用相同fresh W0、同r8初始化来源、原合法FIT/SPLIT、顺序、19task/87更新、原AdamW/逐stage LR/clip/精度/生成设置。若后续实施，须沿既有1% FIT探索条件固定一次，不能根据本提议换数据设置。三臂共同的适应坐标不超过540,672。soft没有额外router参数，避免用新增学习容量解释收益。

特征及在线分组可作为一次共享的当前TRAIN准备，在三臂训练前按合法task时序生成并封定；不得提前生成未来task。soft和Shared不据此改变更新。该准备成本单列，不能因两控制不需要它便把hard称同计算；hard部署还需每个未缓存问题的额外W0前向。

hard相对soft同时改变token→QA、soft→hard、分组来源及活跃rank。三臂能回答“这个粗简化整包是否足够”，**不能单独识别硬选择、原型或token粒度的因果**。若soft较好，只能承认此细粒度软包在本小银行中有价值，不能宣布token路由普遍必要；进一步拆因果需要另一个有必要性的问题，而非本文自动追加第四臂。

## 一个不能隐藏的部署合同

冻结特征必须始终来自同一个原W0。若把共享r4 fold进W0，提取的就不再是原冻结特征；为修正而再藏原W0、共享增量或第二个encoder也违背简化目标。因此本提议的最小一致实现是：**条件图保留原W0以及全部显式r8 A/B，特征前向时关闭全部adapter。** 不能同时宣传原W0特征和全部fold。共享控制的主机制比较也保留同样显式r8表示；普通LoRA可常规全fold的部署机会必须如实列出，不能被排除来制造优势。

设计账面如下，均待真实图及完整重载核实，未测GPU峰：

| 项目 | 数量 |
|---|---:|
| 原完整W0 FP16 | 893,675,552系数／1,787,351,104 bytes |
| 总r8 A/B FP32 | 540,672系数／2,162,688 bytes |
| 完整W0＋显式A/B | 894,216,224系数／1,789,513,792权重bytes |
| 两个896维FP32中心 | 最多7,168普通buffer bytes，另有效组标志 |
| 原可重建普通buffers | 9,032 bytes，仍单列 |

中心不伪装成0参数/0存储；训练期特征缓存、质心和/计数、梯度、Adam状态、输入展开和额外问题前向全部另记。包不包含旧完整专家、teacher、第二W0、隐式原模型依赖或历史QA推理检索。

对原PAS保存权重2,350,437,760bytes，固定小银行有明确的持久字节削减空间；它并不小于同骨干普通r8。PAS原FP32专家与本图小FP32因子的表示差异、七位置→q/v的变化均要公开，不能把全部内存差归原型。硬选择少算私有分支可能降低临时计算，但额外冻结问题前向也可能抵消收益；只有包含特征提取的真实同卡窗口能判断，不能由参数式保证GPU更低或更快。

## 结果怎样改变设计

用户不再要求每域均不低；因此实施前若准入，应依据人类允许的总体质量退让与实际完整内存做一次固定取舍，不在看到结果后设有利容差，也不以PAS正式TEST对本探索DEV作质量排名。

- **Shared总体不低于两条件臂，且其最终部署更简单/更省：** 选择共享，拒绝本固定条件分工的必要性；不能因hard分组非退化就保留模块。
- **Hard在可接受质量退让内、实际GPU/完整成本有优势，且soft没有值得支付的质量收益：** 保留粗分工作为简化候选。正结果只支持这个小银行与在线规则，不把原型本身称原创或声称已解释PAS高分。
- **Soft具有值得支付的质量优势而hard不足：** 承认该细粒度软条件包在本预算下更有效；不继续搜hard种子/组数/温度/补rank。它不自动证明所有token路由必要。
- **两条件臂都差于共享，或额外特征前向使GPU不降：** 关闭这项简化；不能用激活rank少、路由一致或聚类统计替代功能/资源结果。
- **中心/选择实际退化：** 如实报告本在线规则未产生预期条件分工；结果不能支持“输入对应的专门化”解释，不临时增新资格层或自动重新初始化。

主要功能证据应是各task学习前→刚习得及总体最终Answer F1，正负完整报告；不优化遗忘、不按单域调规则。TEST仅留正式确认用途，本文不授权访问新TEST、按其结果选方法或自动完整确认。完整权重、受控GPU窗及训练/额外前向成本共同决定候选是否值得承担；不能用实现通过、同参数量或聚类成功称论文目标完成。
