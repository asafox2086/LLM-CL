# Independent four-domain deployment measurement (prepared, not executed)

`resource_worker.py` is an independent read-only adaptation of the original TaskGrad S19 resource worker b3f4fc9630c1622d05829f5b32eb5fb9d0fce7d98b8101b9026cbea7a3979ca9. It requires the actual successful FINAL_RESULT/FINAL_VERIFIED/COMPLETE, real supervisor exit receipt and actual saved S16 metadata/config/CP SHA. These post-completion values are not prefilled. No new binding, model run, QA access or resource result was produced while writing this source.

One fresh strict GPU reload of the evaluated S16 complete graph is measured on the original physical GPU1/UUID. Original checkpoints.load checks the complete payload SHA and retains native dtype/placement/RNG; no fold, cast, export, reconstruction, optimizer, backward or F1 occurs. The method must remain deployed/counter16 with 48 dense q/v sites, empty A/B/TRAIN context, and every fold-after digest and complete parameter/buffer digest identical to the evaluated graph. Parameter storage is counted by actual unique storage, with buffers, dtype totals and reachable model/payload CUDA references audited separately. Loading cost and load peaks are reported separately from inference windows.

Only natural, medical, geography and finance are measured: the original per-domain hash-min frozen DEV inputs from the sixteen-task manifest and original split. They must equal the first four records of the original PAS five-window proof 45bb9f4ca6d233b139f3c6a9b0255d29eee07e160b085fcef487bad8a3d8d7cd; raw image/text contracts and actual prepared/transport tensors must match each corresponding record. There is no traffic generation. The original GPU visual preparation and fixed 32-token generation/finite-logit guard/synchronized token clock loop are unchanged. TTFT and generation of the remaining 31 tokens retain the original timing definition, including input preparation and instrumentation, not production speed.

The primary peak is the maximum over these four windows. PAS comparison also uses only its same first four per-window peaks, never the old five-window maximum 2959.415 MiB. All per-window values are retained. Historical PAS was trained over five domains; matching measurement inputs does not make its quality a matched four-domain endpoint or establish a quality/resource Pareto claim. This probe does not measure full-TEST worst-case memory. A future metadata-only resource verifier will require true worker exit0/gone and consume these records without new F1 scoring. The fixed model budget remains 600 seconds; there is no added controller, queue or allocator.

CLI remains `--root ABS --output NEW_ABS --binding ABS --gpu 1`. Binding schema is `task-gradient-four-domain-resource-v1`; descriptor keys are documented at the top of the worker. The six tensor/reference/generation/storage/raw-contract helper functions and the entire per-window preparation/generation/timing loop are AST-identical to the original worker. Changes are source/terminal provenance, stage16 structure checks, four selected inputs and output scope labels only. Original measurement helpers (storage/readouts/clock), runtime/environment and package-version pins are supplied from the frozen original measurement contract. Actual terminal/CP hashes must be filled after completion and reviewed before any execution.

Independent review: root and baseline_review checked the quality-producer fields, original checkpoint-load contract, generation dictionaries, fold hashes and unchanged measurement loop. Source preparation is accepted; no metadata validation against a completed run, GPU reload, measurement or resource binding has yet occurred.
