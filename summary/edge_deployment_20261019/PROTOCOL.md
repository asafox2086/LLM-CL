# 手机／普通CPU部署：质量与成本共同评价

目标是在冻结1%数据条件下提高五域最终原始Answer F1，同时控制实际端侧成本。不预设两个模块、LoRA数量或某个论文就是最终方法。GPU研究仅用新GPU1，其他GPU与基线不受影响。

## 主表的部署指标

| 指标 | 具体含义 |
|---|---|
| 最终部署MiB | 实际导出的全部必需模型文件：语言基座、视觉编码器、投影、常驻LoRA／专家／路由、必需检索索引和配置。不是训练checkpoint大小，也不是新增参数单独的大小。 |
| 新增部署MiB | 最终部署包减初始基座完整部署包；必须保持文件格式、精度、运行时和文件计数口径相同。修改原参数的数值不等于新增参数，可合并的适配按实际导出后文件计量。 |
| CPU峰值RAM MiB | 独立同PID进程的完整推理峰值RSS，包含模型、视觉处理、上下文缓存、路由和实际临时张量；同时保存加载前／加载后／推理后RSS、PSS、USS，不能拿参数字节数代替。 |
| 首词延迟s | 模型已加载后，从收到原始图文请求到首个输出token，包含图像处理、视觉编码、prefill和第一次解码；加载时间另记，不藏在计时窗口之外。 |
| 生成速度tok/s | 首token之后的实际解码token数除以对应时间；固定生成预算、batch1，另外保留完整请求时间。 |
| 常驻适配器数 | 端侧为完整推理必须常驻的独立适配／专家数；同一个LoRA的多个层不算多个专家。未证明可无损合并的分支仍须计入。 |

MiB统一为2^20字节。部署包清单、文件SHA、对应训练checkpointSHA、输入协议、CPU型号、指令集、线程数、运行时版本、精度、上下文／图像预算与原始逐请求时间必须可追溯。运行时依赖大小另报，不能通过少算依赖包装优势。

正式五域性能列继续由原完整19阶段／74格／21454QA证明填写。部署测量必须绑定同一最终模型。量化、剪枝、专家删除／近似合并等若改变输出，作为单独部署设置重新核验质量，不沿用原模型F1。原样导出及合并也先检查实际输出一致性，不假定无损。

手机和桌面CPU分开标注。服务器CPU测试只是代理，不代表手机温度、功耗、持续速度或实际内存约束。没有目标硬件实测就不宣称手机端已获优势。当前所有部署主表格留空。

## 从一般问题出发，不做单篇论文优化报告

| 一般问题 | 如何检验 | 可以提出结论的条件 |
|---|---|---|
| 少量数据／少数更新是否使新增分支贡献弱，却保留了部署成本？ | 以共同训练数据比较连续共享、保留历史分支、合并／移除分支，分别记录贡献和部署成本。选择及校准只用TRAIN；预先指定的正负条件均保留。 | 在多个代表方法或不同骨干重复出现，并以完整五域F1和实测成本确认；不能从一个方法低分泛化全部架构方法。 |
| 训练时的保护表示是否需要一直保留到推理？ | 审计优化器／正则统计／SVD因子／参考副本／路由的实际调用依赖，区分可精确折叠与依赖输入的计算。所有基线先做同等、已验证的常规导出清理。 | 删除后函数及完整评测不受损，资源确实下降；这种常规工程清理不单独包装成算法创新。 |
| 参数量小是否真的等于CPU上快、占用小？ | 对同一模型比较可直接部署的静态算子与动态分支执行，实测视觉阶段、prefill、decode、缓存和峰值内存。 | 同硬件、精度和输入预算下质量／成本同时成立；训练参数量不作为推理速度证据。 |
| 低数据训练得到的更新能否以更小的固定结构保留？ | 以已有高分方法为质量参照，检验共享更新、训练后折叠／压缩等预先指定条件；不能以TEST挑层、秩或阈值。 | 至少跨两个代表设置验证共性，保留不能压缩或导致损害的反例。不是只针对一个作者实现的补丁。 |

当前LLaVA正式完整结果中，OSFT是已验证质量参照（AP46.357，SeqFT40.286），但两者训练参数和学习率不同，不将其优势当成单一机制的因果证据。Qwen使用其自身已完成结果比较；跨骨干不混排方法优劣。连续LoRA-RITE及原TRAIN-only对照保留，不因新评价目标丢弃负结果或停止基线。

**现阶段结论：** 已有Qwen参数分析说明，全量训练改变的是同一适配器的幅度、方向和层间分配，并未新增容量；自然任务又否定了“改得更多必然更好”的简单概括。它支持检验有效更新与部署开销，而没有证明某个通用模块已经无效或可直接删除。
