# ShortFixed内存随阶段变化：固定参数不等于固定进程内存

问题来自用户“这个架构内存不大、性能很好吗？内存增长怎么样”。这里只消费原ShortFixed已完整封存运行的资源标量，19阶段使用同一封存运行（原worker PID7170）、同一stage_training_end_persistent口径；不启动模型/张量/QA/优化/GPU，不重评分或bootstrap。相邻任务、输入长度及阶段样本数不同，这不是单独操纵任务数量的增长实验。

事实与解释边界：

- 监控报告的model_parameter_bytes在19个阶段末均为1526762560，trainable_parameter_bytes均为357940224。原监控按model.parameters()计数，不包括U_high等注册buffers，不能把这个字段当完整模型/推理包字节或证明一切常驻状态不增长。
- 阶段末GPU allocated为2.958–2.972GB；S1→S19增加约14.61MB。reserved从3.286→4.236GB，NVML从3.662→4.612GB，两者首末各净增加约0.950GB。这支持区分“该phase存活张量基本稳定”和“进程/分配器预留显存仍增长”，这些阶段末值不是训练瞬时峰值或推理峰值；不能把NVML增长直接叫新增参数，也不能宣称整GPU内存恒定或旧OSFT同设备峰值优势。
- CPU RSS阶段末S1为4.637GB，S3–12约4.728–4.790GB，S13暂升5.104GB后S14–16约4.743GB，S17/18/19分别5.548/5.746/6.077GB。USS亦在后段上升到5.715GB。因此这次轨迹不是每阶段都线性增加，也不能说后段已稳定或长期有界。训练前1.482GB到训练后6.077GB的端点差不能单独推任务增长机制。
- 可定位变化出现在何种观测区间，但不能仅凭这些快照把CPU增长归因给内存泄漏、SVD、缓存、保存、诊断或allocator；本次不追加因果测量/工程优化。即时峰值与周期采样峰值、allocated与reserved/NVML、RSS与USS分别保留，不互换。

结论与行动：ShortFixed没有按任务追加一套模型模块，但“参数规模不扩张”不等于“进程内存恒定”。现有记录不足以称它低整模内存、高性能或推理压缩；21.34%仍只指梯度与CPU Adam两moment张量的对应下降。质量仍只是已探索100DEV的既有信号，PAS参照质量缺测，原完整确认分支保持关闭。该报告补充回答用户内存增长，不是新内存优化/算法收益，不启动新模型或恢复已关闭任务。
