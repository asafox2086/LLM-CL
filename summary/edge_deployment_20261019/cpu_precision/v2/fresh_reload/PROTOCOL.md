# 真正另进程部署重载：不从训练图或原预训练权重恢复

三条件FP32／decoder INT8／all-linear INT8均完成之后，CPU观察器依次在三个独立新进程中执行。原精度测量期间只做CPU等待，不加载模型、不占GPU，不与测量并行竞争CPU。故障保存，不自动重试或放宽精确门槛。

只从对应部署包的config构建模型，按包内runtime_spec指定的模块名重建标准动态INT8拓扑，再mmap读取同一包的model_state.pt严格加载；不读取训练checkpoint或初始HF预训练权重。逐一核对实际文件SHA和全部state_dict条目（包括量化packed权重／bias tuple）的精确值。

每条件随后用相同五个固定TRAIN原始图文请求重新生成强制8token，逐值精确对照原测量repeat0。没有TEST、校准、优化器或新F1，输出不一致则留下失败，不将旧分数用于新部署模型。重载代码、源COMPLETE、包SHA、PID、CPU加载前后／加载窗口10ms RSS峰值和加载耗时均保存。共享加载器代码大小单独列出，PyTorch／Transformers等运行库依赖不藏为零。

这是部署可重现性验证，五题精确仍不等于完整21454QA质量、手机支持或端侧优势。原精度源码与READY不修改，当前正式主表部署值继续留空，直到有同设置完整质量和实际资源的对应证明。
