# 全INT8：五个固定TRAIN请求的先行质量对照

FP32来自保留的v1运行，全INT8来自v2；v2仅改变已替换模块的审计引用生命周期，FP32算术不变。两条均完成全部五题，已独立用冻结原评分函数和全部原参考重算；v2 fresh FP32与decoder INT8尚未完整，不能称三条件完成。

| TRAIN请求 | FP32 Answer F1 | 全INT8 Answer F1 |
|---|---:|---:|
| TextVQA:12860 | 100.000 | 0.000 |
| SLAKE:144 | 100.000 | 100.000 |
| RSVQA-LR:6002 | 100.000 | 0.000 |
| FinMME:2606 | 0.000 | 0.000 |
| CODA-LM:Train:Train_general_1804 | 23.229 | 0.000 |

结论：至少在这些固定训练请求上，直接全部动态INT8不能安全保持已有功能；文件更小不等于可沿用原F1。医学保持100，而自然／遥感100降0，不能推导所有领域／测试集都退化，也不能先归因视觉编码器。全INT8还改变了投影与lm_head，仅decoder条件不改变这些部位；原全部条件保留。

这些是单题TRAIN分数，不是域内测试均值、AP或完整21454结果。共享CPU负载且v1／v2运行时间不同，不以先行数据声称正式加速／内存优势。新的真实部署重载观察器等待三组完成后独立执行；当前包尚未获得该完整证明。

文件字节也是当前序列化／计算精度设置的事实：FP32镜像不是最小的公平存储基线，原模型可保留FP16文件、加载时升精度。最终必须给所有方法同等无损存储优化机会，不能把FP32镜像膨胀当作INT8算法收益。
