# 新独立控制：逐输出通道权重量化

动机来自已完成的原五TRAIN对照：默认全INT8在自然／遥感样例100降0。原三条件全部保留，不改源码／READY／计时或预测。现在只增加一个标准粒度控制，不预设视觉模块是原因，也不是MBQ完整复现或原创。

仍从同一OSFT静态导出包开始，原五个固定TRAIN请求／seed42／2CPU线程／8token预热+三次8token速度+64token自然停止质量、FP32非量化部分／fbgemm／所有327个原线性层相同。唯一数值干预是将默认逐张量权重qconfig改为PyTorch2.6的per_channel_dynamic_qconfig，每个输出通道单独scale，activation仍由同一dynamic INT8内核处理。不增加LoRA、训练、校准数据或优化器，不读取TEST。源代码增加327层实际qscheme／axis0／scale数量和有限性硬门槛，保存真实包及CPU前后／峰值。

三组原条件与新组都保留。新组是TRAIN观察后的固定标准控制，不用TEST选择粒度或阈值。当前可与旧CPU研究流同时运行，各2线程、总至多两个CPU模型，服务器负载不同，因此成本仅可行性，不作为正式加速比。科学源在READY后冻结，故障新版本，不盲重试。

量化布局／实际FP32非量化权重会影响文件大小；最终须给FP32／FP16基线同等无损存储优化，不宣传相对膨胀FP32镜像的虚假压缩率。独立新进程严格state／原五题8token重载仍需完成；仅五TRAIN不填正式Ours，不是完整21454结果。
