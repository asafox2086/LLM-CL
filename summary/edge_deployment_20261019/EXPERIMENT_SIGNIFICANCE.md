# 实验启动前：意义和预期信息

执行规则见[028](../../rules/028_experiment_significance_before_execution_20261019.md)。以下是每项新研究协议应回答的简表；不是新的实验完成证明。

| 项目 | 必须回答 |
|---|---|
| 问题 | 哪个有依据但尚未解决的具体问题？ |
| 对照 | 哪个干预能排除或区分什么，或检验哪项明确改造？ |
| 正结果 | 会支持什么，下一步做什么？ |
| 负结果 | 会否定或限制什么，下一步停止／更改什么？ |
| 目标 | 如何推进1%多领域F1与真实CPU／GPU部署指标？ |
| 成本 | 多少QA／更新／GPU时间，何时结束，需何种完整确认？ |

工程检查单独登记，不将导出成功、重载精确、算子加速、源码审计或排队启动当方法成果。已有CPU局部对照只保留其明确范围；最终目标仍未实现。

当前待回答的架构问题是：原方法哪些扩展确实带来持续学习收益，哪些可以删减或避免。先依据实际作者实现定义容量，再设计最少且可区分的质量／开销对照，不预设全部专家冗余，也不把仅少调用几个分支的常数优化当作论文贡献。
