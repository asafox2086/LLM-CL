# 结果出来前固定解释边界

本页不改任何已冻结科学源、rank、学习率、QA、顺序或评价。它澄清六组究竟控制什么，避免结果出来以后才选择说法。当前六组都没有GPU STARTED／训练完成证明。

## 同总rank不等于同激活宽度

| 条件 | 存储的总rank | 单次输出涉及的低秩宽度上界 | 作者forward实际计算宽度 |
|---|---:|---:|---:|
| CL原8专家 | 64 | 8×8=64（soft混合） | 64 |
| CL共享同rank | 64 | 64 | 64 |
| CL共享小rank | 8 | 8 | 8 |
| SMo原8专家 | 128 | 2×16=32（视觉／指令各选1） | 128（仍计算全部专家） |
| SMo双分支同rank | 128 | 2×64=128 | 128 |
| SMo双分支小rank | 16 | 2×8=16 | 16 |

“宽度”指执行的低秩通道数，不是完整非线性函数的数学秩、FLOPs实测或内存大小。SMo还有输入相关的双分支融合，不能将整层简单当线性rank相加。

因此：CL前两组控制相同总参数预算和总低秩宽度；SMo前两组只控制相同存储总rank，减少分组会扩大被选择专家的宽度。后者若改善，只能支持“同参数预算下少而大的专家优于多而小的专家”这一配置结论，不能唯一归因路由有害或专家数据不足。两家较少分组的同／小rank配对才能检验这个固定结构内较大rank的作用。

## 不能预先讲的故事

- CL为soft混合，各专家可以从同一批TRAIN接收加权梯度，不能说每专家只看到1/8训练数据。SMo的hard选择可能产生不均匀有效曝光，需要真实梯度／选择记录，不能直接假定有多少死专家。
- 两家在当前端口都从第一阶段建立固定池并持续更新；不是每阶段重新冷启动。原独立新专家冷启动反例不能直接当作这六组的原因解释。
- 少专家同rank时，A/B主要乘加量不按专家数成倍降低；router、kernel数和调度成本会变，但局部卡常收益不能当学术主贡献。原SMo未选专家仍计算是作者实现性质，修复稀疏dispatch本身不算新方法。
- 六组都是1%实验，能回答本1%协议中扩展是否有用，不能独自证明“因为数据少所以无用”；不能在没有不同数据规模对照时声称该交互已确立。
- 点估计相近或统计不显著不自动证明等价。只报告本配置、单seed、单骨干结果及完整资源，避免“所有MoE／所有领域都不需要扩展”的泛化。

## 与完整目标的关系

如果小配置质量更好，只获得一个较小适配容量的质量参照。OSFT已经可以常规折叠成无常驻专家的稠密模型；减少MoE适配器不自动使完整模型小于或快于它。是否达到用户目标仍需相同质量与设备口径的完整包、推理内存、TTFT、tok/s实测，不能用meta字节或训练内存代替。
