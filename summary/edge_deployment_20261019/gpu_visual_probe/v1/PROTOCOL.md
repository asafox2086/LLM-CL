# GPU1：最强已完成基线的视觉计算与表示冗余

目标是以正式1% OSFT最终参数为质量起点，测量通用视觉输入冗余是否能减少端侧推理成本。它是可行性探针，不是已完成的新方法或最终性能。个人电脑CPU／GPU均属于端侧；本项在服务器的消费级RTX3090显卡上测量并披露平台，不冒充手机实测。

## 预定比较

同一原始图文输入、同一OSFT最终权重，保留四个条件：

1. **静态稠密基线**：按原GPU FP16 autocast算术一次性重建OSFT权重。168个算子必须逐值相等，五个固定TRAIN请求的前8生成token及视觉特征必须精确复现原动态执行。常规折叠作为基线工程，不算创新。CPU导出没有证明GPU算术等价，本实验直接从原图模型开始。
2. **完全相同视图复用**：仅将同一请求中逐像素、同dtype、同shape精确相同的视图编码一次，投影后按原位置恢复全部特征。保留所有原视觉token和位置。批量大小可能引起浮点误差，必须记录特征SHA、生成及TRAIN分数，不能从输入相同自动宣称模型输出相同。
3. **均匀保留50%内容token**：全部图像结构换行token保留，原顺序保留；不删原图、文字、问题、答案。它是固定token预算的简单控制。
4. **作者DivPrune保留50%内容token**：同预算、同结构token规则，使用CVPR2025作者固定revision 799e2d9的原两函数，不修改选择器。出现重复选择或非有限特征则留存失败，不静默修正或改变预算。论文原默认预算不同，这里不是完整原配方复现。

参考：[DivPrune CVPR2025](https://openaccess.thecvf.com/content/CVPR2025/html/Alvar_DivPrune_Diversity-based_Visual_Token_Pruning_for_Large_Multimodal_Models_CVPR_2025_paper.html)。常规去重或导出本身不作为算法贡献；需要后续跨方法／骨干与完整质量证据。

## 样本与测量

固定五个原TRAIN请求，与CPU探针相同：TextVQA、SLAKE、RSVQA-LR、FinMME、CODA-LM各一条；seed42 ID哈希选取。无TEST输入、答案、预测读取。每条件每请求显式一次8token预热、三次强制8token计时、一次最多64token自然停止TRAIN生成。原动态参考另各8token。全部条件执行，不按结果取消负条件或选择容量。

计时从原始请求开始，包含公共预处理、视觉编码、选择、prefill、首token；后7token测生成速度。GPU同步计时，记录选择开销、视觉时间、同PID CUDA allocated/reserved前后和推理峰值、CPU RSS/PSS/USS前后。模型加载另记；无跨请求视觉缓存。这里不是纯模型训练峰值，也不是完整测试Answer F1。

研究仅新GPU1，实际空闲、无其他GPU进程、显存小于500MiB且利用率小于10%、我们最多占新机三卡才启动。一研究流；不打断他人、基线或既有GPU。当前GPU自然结束后该部署探针优先，原12格／RITE／全部完整确认仅后移保留。科学源及READY冻结后故障新版本，不热改或盲重试。

完整目标仍是五域最终Answer F1略高于最强基线、实际端侧成本显著降低。本探针不填正式Ours或主表部署值；后续候选须同协议完整21454QA确认，选择与校准仅用TRAIN。
