# 两处零训练重分解控制：不把数值漂移当学习

主CPU谱分析已封存，观察到OSFT的有限权重变化有明显高秩尾部。解释前补充测量校准：这些变化是否可能仅由反复SVD重建造成？

只检查主协议预先指定的layer0/q和layer23/down，不依据F1或谱筛选层。对同一原基座，使用checkpoint内绑定的原作者create_svd_dict／reconstruct_weight_matrix、相同75%保护秩及原FP32分解／FP16输出条件，在CPU执行初始分解与18次阶段边界重分解，共19次；不执行模型前向、优化器、反向或任何QA。固定两线程，不比较dtype或优化数值性能，不改模型或队列。

每步记录相对原权重的变化，最终和原已封存OSFT实际变化比较范数、余弦及rank8保留；报告全部两层。若零训练即可产生相近规模／形态变化，就不能用原谱支持低秩容量不足；若明显更小，只能排除这两层在此CPU重分解路径的充分解释，不代表GPU原训练轨迹已经被精确重放，也不能把差额叫“有用学习占比”。原训练SVD在GPU、此控制在CPU，后端差异单列。

这是必要的测量解释控制，不是新精度路线或F1改进。它不选择层、秩或方法，不取消GPU四组小测。预计两矩阵×19次CPU分解，数分钟，完成即停止；完整原参数、源SHA和前后CUDA未初始化记录，失败保留、不盲重试。
