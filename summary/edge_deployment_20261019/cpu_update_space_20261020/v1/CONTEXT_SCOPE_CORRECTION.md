# 重建上下文范围更正

K59的96.67%、8.20%等数值，来自原存储因子在**无外层autocast**时按FP32重建、再输出FP16的系数差分。原EVIDENCE、测量源和数值均保留；不能再将其称为已经验证的“原autocast前向实际等效权重谱”。

后续CPU功能小测v1把原模型放在CPU FP16 autocast中运行，却在其外折叠权重，原／折叠首题NLL精确门槛失败。作者核中的矩阵乘法会受外层autocast影响，显式`.to(float32)`本身不禁用autocast。因此上下文不同是一项需要实际算子核验的解释，不能放宽相等门槛，不能沿用失败探针的结果。

独立v2先检查原checkpoint全部168个线性算子在相同原CPU上下文的精确性，再保留相同数值条件重新测量；没有完成证明前不宣称解释已被模型实验确认。CPU验证也不等于原GPU路径的精确验证。

原局部空间维数和无autocast系数谱仍是相应定义下的数据，不是最终F1的原因或部署节省证明。两个零训练控制同属该无autocastCPU重建范围，不作实际GPU漂移上界。

这是我们的测量上下文／表述错误，不是正式OSFT基线故障。正式基线仍使用原未改的训练和评测源，已封存F1不来自本次折叠分析，无须据此重跑。该修复不作为精度、量化、算子卡常或新方法收益。
