# 同坐标预算下，q/v加宽与七类分配的配置比较

## 问题、证据与用途

原四组DEV中，q/v r8为540672训练坐标、宏39.870439；七类r8为4399104、宏41.952549。原协议明确位置与坐标数混杂，候选TEST之前的AGENTS也保留了同预算分配问题。本研究只回答这个先前留下的问题，不解释刚结束的完整TEST差距，不挽救已停止的LoRA_all配置。

最少只新增一组宽q/v，复用已封存原qv与all的FIT/DEV结果，不重训两参照。相同4399104坐标下，比较集中于48个q/v模块与分布于168个七类模块。只匹配可训练坐标数和每适配器乘数，不匹配有效维数、初始化Jacobian、实际权重步长、计算量或优化几何；结论不能叫纯位置因果。

若宽q/v高于all，只能说在此预算/初始化/缩放/更新过程下，额外120位置不是该DEV点估计优势的必要解释，不能宣称等效或参数可删。若低于all，削弱本固定配置下“只要总坐标相同就足够”的解释，停止这个集中预算替代，不证明额外位置必需。差异不清楚则保留未解；不显著不当等效。DEV已经被探索使用，非新验证集或训练seed稳定性证据。

## 唯一干预及冻结值

沿用原SeqLinear的forward、FP32 A/B、Kaiming A、B零、dropout0.1；固定实际乘数scale=4，即alpha=4r（65→260、66→264），LR1e-4。不是保持alpha32导致乘数随rank变小。先完整按原q/v r8初始化，再保留其每模块A前8行/B前8列；额外部分以模块名seed在fork_rng内初始化，不消耗原q/v构造RNG。TRAIN前仍seed42。训练结构改变仍会改变dropout/优化路径，不声称逐步梯度相同。乘数4也不保证宽度稳定性或匹配Jacobian；[rsLoRA固定v1](https://arxiv.org/html/2312.03732v1)只用于提醒缩放影响学习，不采用它的方法、定理保证或第二套缩放。
