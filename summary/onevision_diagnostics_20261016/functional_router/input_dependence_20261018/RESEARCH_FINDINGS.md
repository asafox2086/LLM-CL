# 质量调用是否真的使用输入？以及两模块可能重叠的边界

2026-10-18。仅43条已封存TRAIN缓存，冻结16参数头与全部专家；没有打开TEST问答/预测，没有新增模型前向、生成、LoRA或头训练。2021次微型头调用，脚本内部计时约0.274秒，不含导入/启动时间。此处NLL不是新的Answer F1结果。

1. **探究的问题：** 第二模块是否只是恒定偏向一个专家？如果质量调用主要绕开冷启动弱专家，它和功能继承是否可能在解决同一个损失来源？
2. **做的实验：** 绑定原pilot完成证明、校准文件和此前逐题TRAIN审计的SHA，逐条精确复现原调用。保持原43×4候选NLL不变，分别将43条相似度输入置零、替换为TRAIN均值、反转输入对应关系，以及枚举全部43个循环位移。每种变体只改变质量头收到的相似度，不修改实际QA、模型或部署头；所有位移均报告。
3. **结果：** 候选顺序为base/e0/e1/e2。

4. **证明了什么：** 在这个TRAIN缓存上，实际硬调用确实依赖输入，不是一个常量专家；破坏对应关系会降低该缓存上的调用质量。不过，几何→质量的整段收益不能全部解释成精细逐输入识别，因为单e2本身已避开弱e1。结合e1只学11条/一步的证据，A修复弱习得、B避开弱专家的收益可能重叠。**尚未证明A与B独立、互补、可加或产生新的完整F1收益。** 缓存是专家/投影已见TRAIN，不是泛化测试；人为零/均值输入也不是自然问题分布。
5. **改进的方法：** 不依据此缓存改变已部署头、删除e1、调阈值或添加新候选。保留已准入的冷/温×几何/质量四格，直接看温启动之后B的增量`R11−R10`，并与冷启动时增量`R01−R00`对比。这样可检验B是否仍有独立增益，而不是将两项各自的旧收益相加。
6. **改进的效果：** 这轮是模块解释性控制，没有新增方法成绩。实际GPU组合及完整21454仍待；无论增益重叠、负交互或整体改善，都按完整领域总分、AP及成本报告，不要求每题或每类全面提升。只有最终全测时，FWT/BWT仍不补算。
