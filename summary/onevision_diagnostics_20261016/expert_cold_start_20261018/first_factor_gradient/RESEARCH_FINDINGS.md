# 冷、温启动首步：旧功能与优化通道同时改变

2026-10-18。补充既有K02和冷启动证明链；这是新温启动运行保存的真实梯度/参数对照，不另立一个“新发现”重复计数。

## 1. 探究的问题

完整继承旧LoRA的收益，能否全部解释为旧知识被保留？尤其当当前任务仅11条TRAIN、只做一次更新时，冷、温初始化是否让同样标记为可训练的A/B实际获得不同的学习机会？

## 2. 做的实验

只读两个实际运行T02的原始裁剪前梯度、初始化、训练后适配器和原生T01封存权重。冷池为`learned_cosine_K3/train/20261018_022443`，温池为`warm_inherit_K3_v1/train/20261018_165303`，均在`exp/onevision_learned_reuse_20261018/`下。

两者同11条原TRAIN，实际顺序精确等于既定seed42训练哈希顺序；同rank8、48个线性适配层、一次AdamW更新、正学习率、weight_decay=0。温池T01 A/B精确等于原生顺序T01；T02从实际旧e0完整A/B继承。冷池T02从原初始A和零B开始。源权重/梯度SHA、原冷池完成证明及温池原子检查点SHA均核验。审计仅CPU读取小张量，0次模型前向、0次优化、0条TEST预测，没有改动运行源码或QA。

| --- | ---: | ---: |
| A裁剪前梯度L2 | 0 | 3.392487 |
| B裁剪前梯度L2 | 80.692900 | 39.731776 |
| A实际改变的层数 | 0/48 | 48/48 |
| B实际改变的层数 | 48/48 | 48/48 |
| 实际ΔA L2 | 0 | 0.058455919 |
| 实际ΔB L2 | 0.044298284 | 0.044297544 |

冷启动标记可训练的540672个参数中，A的344064个参数在该唯一更新中梯度全零、参数完全不变；B的196608个参数有非零梯度并改变。温启动A/B均获得非零梯度且48层均改变。**因此，不能仅看trainable参数总数就断言两者单步实际学习条件相同。** 梯度范数更大也不等于实际Adam步更大：本例B梯度相差约一倍，实际ΔB范数却几乎相同。

## 4. 证明了什么

LoRA增量写为\(\Delta W=sBA\)，则\(\partial L/\partial A=sB^\top(\partial L/\partial\Delta W)\)。初始B=0使该分支首步A梯度为0；本例fresh AdamW/零weight_decay又排除了旧优化器动量或权重衰减改变A的可能。这是已知初始化与链式法则性质，原作者[线性LoRA实现](https://github.com/microsoft/LoRA/blob/main/loralib/layers.py)也使用随机A/零B；**不是新代数定理**。我们验证的是它在本1%单更新任务中的真实执行，以及完整继承后的实际激活差异。

这支持对冷启动的更精确表述：**完整继承同时保留初始功能、开放首步A/B联合更新；现有收益不能全部归因于旧知识。** 未证明A零梯度独立造成多少F1损失，也不意味着B没有学习、LoRA整体无效、所有单步阶段或所有论文方法均如此。复用已有非零B的LoRA不受这个特定零梯度条件约束。

本JSON的`first_step_formula`省略固定scale，仅表达零梯度条件；本文公式显式保留scale，实际张量审计不依赖该字符串。原CPU审计v1曾将未打乱的manifest列表误当优化顺序，断言失败；v2改为核验原训练器的既定哈希顺序和冷/温精确一致，未改任何ID或训练顺序。保留两个审计源，不以此宣称数据划分有问题。

## 5. 改进的方法

继续既定模块A：必要时新增专家，完整继承TRAIN几何规则所选旧专家A/B，再按相同原预算训练。它不增加Kmax3/rank8，不重置已有能力，并在本例让A从首步即可更新。只继承A再清零B，仍会遇到该首步A零梯度条件；已有A-only控制也没有复现完整继承收益。

模块B仍是TRAIN功能质量校准调用：输入相似不能保证被选专家最会回答。此次梯度证据只补充A的机制，不能作为B已成功的证据，也不新加第三个模块。原冷/温×几何/质量四格与全部18数据量控制继续。
