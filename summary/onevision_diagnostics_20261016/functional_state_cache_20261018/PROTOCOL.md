# 连续LoRA与有界功能状态：先做TRAIN筛查，不新增GPU任务

2026-10-18，在读取本筛查损失矩阵之前固定本协议。依据：当前继承医学专家精确等于普通顺序LoRA对应前缀，100题NLL相同；输入几何不变而功能质量变化，现有组合对简单参考的诊断优势仍小且不确定。

目的：检查是否可以持续复用一个LoRA训练流、仅保留少数有价值的历史状态，再以TRAIN功能质量调用，避免把训练分散到冷专家。它是现有两问题/两模块方向的后续筛查，不代表替换当前已冻结方法或已完成新算法。

本次只读原生确定性SeqFT封存的19状态×原先固定20条TRAIN探针NLL（原研究每域4条）。主训练仍是原1313 QA/93次更新；该20条是诊断内存，不是全TRAIN，不是验证/测试集。每条QA按原native任务记录到达阶段。决策在t阶段只能访问已到达QA、已有缓存与当前状态t；原文件中预先记录的未来QA损失在到达前必须屏蔽，不使用未来模型状态。

固定比较Kmax=1与3。当前状态必须保留；候选为上轮保留状态加当前状态，枚举最多Kmax的子集，以“已到达TRAIN探针上逐题最低NLL的均值＋0.02×额外状态数”选择。0.02单位为每QA的nats，是预先固定的复杂度容忍设置，与旧功能预算同量纲；不是由TEST调参得出，也不宣称由旧预算公式推导。相同目标时优先少状态、再较新状态。不得查看本筛查结果后改罚项并只报告赢家。

逐题最低NLL仅作TRAIN功能覆盖目标，不是部署时用TEST答案挑状态。Kmax3得到的是小候选集合上的逐阶段最小目标，不是全局或TEST最优LoRA数。记录全部19次选择、到达QA、实际覆盖损失、虚拟在线需要的模型/QA查询数、源/数据/权重SHA；没有新增模型前向，不能把已有损失称为真实零计算成本。

若后续实现GPU候选，两个模块可分别是：A连续共享训练＋有界功能状态保留，B以TRAIN质量学习图像/问题到状态的调用；具体内存采样、路由器、完整数据和CPU/GPU资源需另行冻结与验证。本次没有实现或准入该候选，不给出F1收益、不增加专家或插队。当前全部四视图、18数据控制、既定完整21454和两机基线继续。
