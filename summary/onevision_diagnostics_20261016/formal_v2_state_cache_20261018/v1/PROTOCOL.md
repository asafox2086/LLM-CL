# 两模块公共协议版：连续习得＋功能缓存

本协议在任何本候选的真实GPU构建/预测前固定。纠正研究原生设置与正式基线不一致的问题，不根据已有155题分数选超参、视图或候选。原生研究与所有旧作业保留，不混入公共主表。

## 问题与模块

问题一是极少更新下新专家冷启动的弱习得，已有局部控制支持，不能推广为永久容量上限。模块A保持一条rank8 LoRA连续习得，缓存最多3个功能状态，当前状态必留。问题二是输入几何熟悉不等于功能适用；模块B用输入相似度加权TRAIN锚的各缓存回答NLL，调用一个估计损失最低的状态。仍未证明公共完整测试有大幅收益。

沿用同一候选已经固定的20个TRAIN锚、每阶段最多4个TRAIN原型、Kmax=3、额外状态罚项0.02nats、质量核温度0.1，不做新搜索。QA和状态按19原生阶段到达；不接触未来QA/状态做缓存选择。动态保留数量不称最优LoRA数量。几何关闭/质量开启两种调用均报告，不能根据诊断删除完整候选。

## 完全共享正式训练轨迹

冻结1%1313TRAIN、19原生任务、seed42、1epoch、有效batch16、rank8/alpha32/dropout0.1。主训练使用已经完整核验的正式OneVision SeqFT-LoRA原19阶段checkpoint，原始全部93次更新的学习率/loss/梯度及资源成本仍计入。模块A的缓存选择与模块B调用不反馈主优化器，因此可以精确复用这条已训练轨迹，不再次训练，也不改变数据顺序或RNG。

CPU逐阶段校验约1.93GB的原完整checkpoint SHA后，提取96个FP32 A/B张量（540672参数），逐元素比原图及独立CPU重载精确一致。19个小适配状态共约40MiB仅为来源档案；部署池最多3个，选择时临时候选最多4个。不能把磁盘来源档案当19个常驻LoRA，也不能隐去加载、候选、优化器、原主训练、CPU/GPU与额外计算成本。

研究原生版除图像/精度外，也有不同TRAIN哈希顺序、逐阶段RNG重置与确定性后端等实现差异；正式版不搬用其训练参数、预测或资源数。使用原正式checkpoint同时消除这些主训练差异，不把“相同数据”误称“相同轨迹”。

## 输入、评分与核验

模型为同一LLaVA-OneVision-Qwen2-0.5B-OV；FP16基座/FP32适配参数，401408像素图像预算、128MiB公共视觉CPU缓存。直接导入未修改的正式Factory、input_batch、answer_loss、evaluate、原任务instruction/max_new_tokens、greedy生成、512目标截断和评分。唯一主Acc仍是原始Answer F1；不翻译、剥前缀、映射选项或抽取答案。

真实GPU首先通过原公共OneVision官方前向/生成门槛，包含既有Fin5082几何正控制。缓存选择只用TRAIN，20锚的回答只计算TRAIN质量；TEST的答案、题型和领域不进入调用。输入特征为原始问题词嵌入与公共图像特征的归一化拼接。任务instruction由所有方法共享的输入框架处理，不作为路由标签。

完整构建后报告全部四格：seq_geometry、seq_quality、cache_geometry、cache_quality。同155题的单状态两格必须相同，并且逐题原预测/金标/全部原评分精确等于正式SeqFT已有155题预测；若跨硬件FP16或实现差异导致门槛失败，保留故障并停止，不放宽或宣称方法收益。

两个缓存调用格无论诊断分数如何都做完整21454确认。每个独立新进程先精确重载该格155题，再完整测，不拼旧部分输出。最终单点不能推导完整FWT/BWT，仍需该方法的初始及稀疏当前/下一任务格；缺少时保持null，不借旧研究或其他调用的值填补。

保存19阶段pool、TRAIN质量/原型/决策、逐题路由、全部原始预测、源与数据/状态SHA、实际额外NLL/特征调用、原训练来源和本进程CPU/GPU前后/峰值。来源checkpoint与小状态、原始QA和模型不入Git。公共与研究表分开，完整确认前正式Ours留空。

## 执行顺序与边界

只由唯一研究CPU队列在当前GPU作业自然完成并核验后准入，GPU0/1择空，保持一个研究流、新机我们的作业最多占3卡；两机正式基线持续。按公共设置公平对比的需求，顺序为保全当前作业→公共构建/四格→两个公共完整21454→返回全部原18因子/原生完整及其他机制作业，原已准入的共享锚依赖优先保留。此顺序由配置一致性需要决定，不按TEST赢家排序。

CPU合成模型/合成QA测试只验证真实driver、保留/调用、公共evaluator及完成判定的集成，不是真模型F1、显存、吞吐或GPU等价证据。当前正式GPU结果只有实际完成证明才计入。
