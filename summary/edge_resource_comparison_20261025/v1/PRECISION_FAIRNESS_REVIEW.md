# 精度口径与端侧结论

**现有图足以支持“原实现、同卡五固定窗的实测内存更小”，不必先补同dtype实验才承认这项事实；不足以把约25%的PAS峰差全部归因于方法结构。** 若论文进一步主张排除dtype/表示后仍有同样GPU优势，就需要有区分力的共同数值口径证据。它是具体主张的证据需求，不是停止当前科研或追加精度搜索的准入门。

以下只据已sealed元数据与源码作整数运算，0模型/评分/服务器/ARC partial。**“统一2字节”是条件化的持久载荷账本，不是已转换模型、质量保证或GPU测量。**

| 完整固定表示 | 原必要权重 bytes | 神经权重全部按2 bytes/系数计算 |
| --- | ---: | ---: |
| LLaVA朴素r8，已fold | 1,787,351,104 | 1,787,351,104（893,675,552系数） |
| LLaVA PAS原图 | 2,350,437,760 | 2,068,893,760（1,034,446,880神经系数）；若保原336个FP32 mask，再加1,344 |
| Qwen SeqLoRA原图 | 4,422,329,344 | 4,420,150,272（2,210,075,136系数） |

PAS的893,675,552基座系数原本FP16；另140,771,328专家/路由等神经系数原本FP32。仅其4→2字节的**算术溢价恰268.5MiB**。即便把这些额外系数按2字节计，固定原神经表示仍比LLaVA单图多**281,542,656 bytes＝268.5MiB**，mask另计。也就是说原537.001MiB持久增加量大约一半是dtype、一半是额外表示，不能全叫架构必要开销。

这是一个有条件的精确下界：只在保全原系数数量、不删改/共享/重编码且每神经系数至少2字节的表示族内，持久神经载荷不可能小于上述乘积。**它不是所有合法部署的下界**，也不是GPU峰下界；不限制其他压缩、按需驻留或表示变化。PAS有168个输入相关路由专家模块，不能直接套普通单LoRA的全局fold删除银行。

Qwen的FP32 A/B仅1,089,536系数：统一2字节最多消去该持久dtype溢价**2.078125MiB**。若再作普通LoRA fold，按原2,208,985,600个基座系数计，FP16稠密载荷为**4,417,971,200 bytes**，仍远大于LLaVA的1,787,351,104；这是主要由骨干大小产生的数量差，不能归新增门。fold后的系数数量可由结构计算，转换后答案是否保持仍没有测过。

**不能从这些数推出GPU峰或F1。** 不能把268.5MiB直接从PAS的每窗峰减去：路由/专家临时tensor、FP32计算、工作区、激活和分配生存期都会影响峰值。更不能把halfcast当无损。已核本地原作者`coinmoelora.py`冻结副本SHA `75d46bcd7850ec3c03d13968f1e4180098d62a1da7ab905df6f9fa1d054a4b6a`，与原source manifest相符：当前`gate_router=a`的forward第650行把输入转为专家A.dtype，第679–682行以该dtype计算路由分数，没有再`.float()`；第719行无条件`S.masked_fill(...,-1e9)`。专家改FP16后路由也走FP16并触及不可表示的填充值；HostedLinear又明确禁autocast。仅转换浮点weights而保原buffer/forward，不能视为已有可合法运行的共同FP16参照；保留FP32 mask或inv_freq并不能改变路由分数dtype。修fill常量或改路由精度会成为新的数值实现，因此**当前不启动cast-only PAS补测，也不为公平性改写路由**。Qwen的小adapter溢价也只能解释持久字节，不能由其很小便数学证明整个GPU峰关系不变。

**对选择的影响：** 当前三臂首先回答新增规则是否提高完整回答，不能靠精度账本挽救阴性方法。若回答证据足以推进论文，现有原实现资源结论及精确系数差可保留，GPU优势限定在该表示/dtype；不能提升为独立于精度的同幅度保证。PAS的268.5MiB实质混杂需要如实交代，但当前不存在经本源码确认的无改forward FP16参照，故不为形式公平扩出数值实现分支。Qwen仅需上述存储敏感性分析，不自动补probe。这里不设新的实验门，不设计配置或授权执行。
