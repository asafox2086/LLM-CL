# 单一原生紧凑载体的元数据资格核对

## 问题与行动变化

此前r200完整先导质量失败，且首次更新前已有更高首批日志NLL；旧预处理历史哈希缺测，不能据此唯一归因压缩致损。当前也没有小载体能承接原层功能的证据。GPU忙期间可先检验另一条具体可行性：已有完整图文预训练的小模型，是否具备作为**同载体参数必要性对照**的接口条件，避免混淆可能的起点不适配与新适应机制失败？本轮只接受SmolVLM-500M-Instruct的元数据资格核对，不下载权重、安装环境或准入模型。

这不是将“换小基座”当我们的方法。其规模和预训练功能属于作者已有成果；后续若要研究哪些专家/更新参数不必永久新建，必须在同一载体、同输入和训练规则内比较。与OneVision的跨骨干差异最多作完整规模—质量取舍，不能归因我们的算法。本轮没有选择具体新适应算法，也不为填时间恢复旧分支。

## 主子agent讨论与去留

最初重访跨层共享时，先查旧framework_design_v1，发现普通共享基+私有残差早已讨论。子agent指出：同一私有AB既补初始层差又学新任务，当前不能分离这两种需求；置换/缩放对齐不消除真实层差。因此不实现、不再开一个CPU权重近似表。

共享非线性SwiGLU字典、层专属输出系数在条件上可构造，但只能改变共同特征跨度内的组合，不能创造缺失的门/输入响应。若必须用私有残差补满或字典接近各层总通道数，就不再有声称的节省。它仍是已知共同特征范式，本轮未将其作为新主框架或实验准入。

我先读过256M官方网页/API/config；子agent建议较温和的500M，以减少再次选择极小容量载体的风险。消息交叉时双方曾分别提出维持已读256M和固定500M，最终明确只对500M收集版本绑定元数据。没有根据本任务成绩择型；256M不成为对照/候选，不下载/启动。500M不因此被证明本任务更好或最优，后续不扩成小模型榜单或安装项目。

## 已核官方声明，非本地模型实测

[官方模型仓库](https://huggingface.co/HuggingFaceTB/SmolVLM-500M-Instruct)版本固定为 `a7da5b986cb59b408707209984f360a5f4ad7e47`。

| 项目 | 本次元数据 |
|---|---|
| 官方API safetensors总数 | 507,482,304，声明BF16；未读权重头/张量核实共享存储 |
| 许可/语言 | Apache-2.0 / 英文 |
| 预训练组成 | SmolLM2-360M-Instruct + SigLIP-base-patch16-512 |
| 模型类 | Idefics3ForConditionalGeneration |
| 文本配置 | 32层，hidden960，intermediate2560，词表49,280，上下文8,192 |
| 视觉配置 | 12层，hidden768，patch16，image512 |
| 原生接口 | 图像和文本输入、文本生成；chat template和图像特殊token |

官方声明规模小于原OneVision核实锚893,675,552，但不能写成我们实现了减重，更不能据此称质量保持。作者卡含“SmolVLM-256 uses64tokens”的复用文字，本轮以实际500M processor配置的 `image_seq_len=64` 为静态依据；不是靠那段文字推形状。仓库整体usedStorage含多种导出格式，不是单一最终模型权重大小，本轮不使用它作为成本。

## 新识别的接口边界

- 图像processor默认开启splitting、整体longest_edge2048、子图上限512。64是每个编码块的静态序列长度，不是任意原图总共64 tokens；裁块/全局图与文本合并后的实际总长尚未执行核验。不以缩图、少图块或截断原答案来人为过上下文门槛。
- tokenizer声明8,192和左截断；不能默认允许静默截断原问题/图像/答案。未来如有正式必要性协议，超长输入的完整性与退出策略必须结果前固定，当前未处理任何QA。
- token元数据存在不一致：generation_config的EOS为49279；tokenizer_config以 `<end_of_utterance>` 为EOS，special_tokens_map以 `<|im_end|>` 为EOS，text_config的EOS为2。需要未来必要实现核实实际加载优先级与停止行为，当前不能据配置宣称原始答案生成接口已经验证。
- 配置和作者示例声明BF16，并不能证明当前环境实际前反向数值路径可用。它与旧OneVision的FP16/processor/tokenizer不同；不搜索精度/量化救分，不写严格同输入数值因果比较。
- 卡声明训练数据The Cauldron与Docmatix，原DEV是否在其预训练中出现未知；不能称严格未见原DEV的teacher，也不使用见过原DEV本地微调的正式teacher。预训练污染与跨骨干差异必须公开。
- 原始问题、图像和全部原参考保持；不翻译、不答案映射，原AnswerF1规则保持。当前只有文档支持接口可能兼容，没有真实输入或质量证明。

## 当前结论与成本

本轮只解决“存在一个声明规模较小、可固定版本的原生图文候选载体”这个缺口，**没有解决它在原五域上的能力、参数扩展必要性或我们的新框架**。一次官方API及6个固定revision配置元数据读取共约1.52秒，原字节仅私有保存，公开EVIDENCE只记录来源/hash/必要字段；0权重/完整tokenizer载荷/QA/模型/优化器/GPU/F1/bootstrap，没有重计旧参数/评分或CPU模型准入。

下一项只有明确同一载体上的参数必要性干预、必要对照、全部成本和正负出口，才有模型实施意义。当前决定是metadata qualification only，不下载、不SFT、不蒸馏、不CPU模型门、不自动新worker。正式七范围索引本轮只读仍7/14，既有FOREVER独立结果保留；没有新正式proof，不重渲染发布。科研总目标未实现。
