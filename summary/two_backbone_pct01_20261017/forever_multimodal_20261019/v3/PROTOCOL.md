# FOREVER 多模态正式入口：共同训练与阶段安全恢复

正式数据为既有冻结 1% TRAIN 1313 QA、19 个原生任务，完整 TEST 21454 QA；seed42。原始图片／问题／答案、原始 Answer F1、样本顺序、主训练一轮／batch16／micro1／LR1e-4／floor warmup／cosine／clip1、FP16基座／FP32 qv rank8 LoRA、401408图像面积上限与128MiB共享缓存均不改变。

回放仍是作者机制的图文接入：原样类别抽样选择历史 TRAIN、24步校准、参数位移模型时间、阶段末两轮请求回放、warmup5／linear，以及强度相关的参考参数正则。实际回放曝光／正LR／作者warmup零步／梯度／CPU-GPU资源独立计费，不把主训练93次更新当作总计算。代码借鉴的是作者机制，不是作者长轮次原实验复现。

模型、输入、优化器、评价和 checkpoint 序列化／重载内核与已通过两个真实 backbone 门槛的 v2 完全相同；新 v3 只改运行 I/O。主 minibatch 训练／梯度／更新循环 AST 精确不变，其他模块逐字节相同，见 `IO_EQUIVALENCE.json`。原活动V2及已运行v1/v2源不改。

- 每阶段完整训练、作者回放和必要评测完成后保存模型；单独写入持久化 `committed_latest.json`，全部阶段文件落盘后才删除更早权重。只保留最新／最终权重，旧权重 SHA 元数据保留。
- 重启恢复只选该提交指针，原图结构／参数 SHA／RNG 校验与加载保持共同实现。新写了权重但尚未提交的分支，连同事件、回放状态、评测和有效性记录整体归档；不把旧中断更新再算进新93次主更新。
- 每个阶段独立事件文件，以已提交阶段重建统一 `logs/events.jsonl`。不依靠手工删行修复重复训练日志。缺有效提交点时拒绝续用不完整权重；原目录保留。
- 全局资源分进程保存；恢复后的窗口单列，不能跨PID相减或冒充整次训练增长。损坏资源样本标为不完整，不补造数据、不使已有效训练的QA结果因资源JSON损坏而丢失。

`ROLLING_IO_CPU_CHECKS.json` 的7项真实文件事务控制覆盖未提交新权重、损坏未来事件尾部、旧权重删除时机、一次性重算事件、运行目录边界和资源窗口。它们是 I/O 控制，不是模型性能实验。GPU模型核及真正保存／另进程加载已有v2双骨干证明；v3不沿用预检权重或预测，正式运行从原始基座新鲜开始。

两机训练源码／manifest相同。旧GPU0运行OneVision；新机Qwen等待原调度器没有可派发的1%任务后使用空闲GPU2，GPU3留给既有基线／原生BF16通道，避免两个CPU队列争抢同一卡。研究0／1不受影响，新机我们的GPU任务最多3张卡。使用nohup，失败保存证据且不盲重试。进程退出不等于结果可发布，仍须独立校验19阶段、74必要评测格、21454最终QA、回放／有效更新、最终参数与来源。FOREVER分数在这些证明齐全前留空。

旧v1保存故障、v2模型修复证明和CPU空闲采样停止全部保留。本文没有宣称F1提升、全方位优势或新算法贡献。
