# 固定执行包超时，方向质量仍缺测

根据本轮终态观察及唯一元数据成本读数，aligned/train在原5400秒预算内未完成，原流程失败关闭并释放slot；没有最终部署／随机臂质量对照，也没有执行原计划600次评分。原源、预算和失败记录保留，不续训、延期或从本次partial选择配置。这是固定设备与执行包下的成本失败，不能称任务方向质量无用。

已持久记录69／87次主更新及144次校准反传。主更新事件计时合计约2746.78秒，校准计时合计约305.74秒，controller phase墙钟约5400.22秒。前两项是producer原计时区间，不是纯GPU kernel时间；phase墙钟还包含Python启动、加载、等待及收尾。校准的额外曝光和反传是真实成本，不能因没有optimizer更新而省略。

其余墙钟没有完整的独立计时分解。逐阶段fold、SVD、摘要／保存等没有单独完整时钟；阶段readout计时在成功训练末尾才统一写出。不能把未分解部分全部归给SVD、readout或某项方法开销，也不能据这些数值声称已定位超时瓶颈。`STAGE_*_COMPLETE.json`写在该stage的acquired读数之前，因此阶段adapter回执本身不证明该次读数已经完整；不补称全部200回答已经完成或封存。

原成本消费者误用`complete_model.pt`检查最终包存在性，而worker真实路径是`complete.pt`。该旧布尔字段不能作为存在／不存在证明，应由独立修正收据说明实际路径，保留原输出；这不需要模型加载或重新评分。本审阅没有据错误字段作质量判断。

即使未来某次完整匹配对照中aligned胜random，也至多支持共同fold/reset学习配方下任务相关方向策略的效用，不能直接写成“可替代扩容或专家”。替代主张另需强基线的完整质量与真实部署成本证据；当前两臂未完成，连这一方向策略比较也尚未得到。

本审阅只读本地冻结producer、成本消费者源码及本轮已报告的终态／标量；未重新执行成本派生，未读取partial回答、训练loss或质量，未运行模型／评分或访问服务器。metadata读取与失败解释不是新的模型效果或科研成功。
