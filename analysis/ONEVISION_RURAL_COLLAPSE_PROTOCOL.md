# 遥感输出坍缩的机制核验（2026-10-17）

这是痛点诊断，不设计新方法，不训练、不改冻结数据或评分。依据已完成基底／预算实验的异常：完整旧AB在原生rural任务从1更新76/100降到4更新44/100，最终100题全部输出urban；随机起点原EM从0提高到62，但固定前缀辅助标签正确数从64变62。

## 要区分的解释

1. 格式适配：生成去掉固定英文前缀后，原EM提升但标签判别未同步提高。
2. 答案先验偏移：训练池urban4/rural2，多次更新将答案边界整体推向urban。
3. 图像区分变化：模型的urban/rural概率是否仍随图片变化，还是只输出常量。常量greedy输出本身不证明视觉输入未使用。
4. 真正训练拟合与泛化：补测相同终点权重的全部6条TRAIN，不能把更新前loss直接配对更新后测试。

## 冻结设置

- 同一原1313 TRAIN池中的T12全部6条，以及原T12全部100条TEST；不重新采样、不平衡重采样、不改变问答和图片文件。
- 五个固定权重：旧自然LoRA未进行T12训练；随机A零B起点的1／4更新；旧AB起点的1／4更新。全部来自已完成、SHA核验的原基底预算实验，不按最优测试分数挑检查点。
- 每个权重均评原图、确定性错图、无图。错图仅在同split内按固定hash顺序轮换，不读答案／类别挑图；路径和文件字节SHA不同。它不保证错图语义一定不同。
- 保存原答案NLL、逐题原生成／原评分，以及四个固定候选字符串（TRAIN标签rural/urban，加固定The answer is前缀）的含EOS完整序列sum/mean NLL。候选只作辅助概率审计，不取代原模型生成、不作路由或测试调参。
- 原图为实际任务，错图／无图明确标为推理消融，不伪装原测试成绩。概率变化不直接解释为完整视觉能力；文本移除改变序列位置，另列限制。
- 记录checkpoint/source/manifest SHA、逐题ID、原始输出、具体CPU/GPU内存前后与峰值。所有参数requires_grad=False，无optimizer；逐权重处理后检查A/B逐元素不变。
