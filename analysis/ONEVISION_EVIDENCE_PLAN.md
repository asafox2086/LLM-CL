# 1%受限小模型：证据保存和分析边界

用户要求从参数、loss、梯度等角度持续分析。活动runner不得热改；新分析只读阶段快照，GPU重计算等待新GPU1空闲。

## 已部署的保存内容（代码核验，不冒充最新文件盘点）

- 冻结原基座官方版本、下载逐文件SHA256；48个q/v LoRA模块，每个完成控制／阶段的完整A/B权重，合计540672可训练参数。冻结基座不重复复制到每个LoRA文件。
- 每优化更新：平均训练loss、裁剪前真实梯度总范数、实际学习率、warmup步数、耗时、GPU分配、最后一个microbatch的token统计（不能把该token统计当整batch之和）。
- 阶段探针：每域2个固定TRAIN样本，平均梯度余弦和探针NLL；未保存该步骤的原始梯度张量。
- 逐题诊断NLL，固定生成子集的原回答／参考／EM／F1／ROUGE-L，原图／无图／错配图消融。
- CPU RSS/PSS/USS、GPU allocated/reserved/NVML和分阶段前后／周期占用；最终汇总只在run完成后生成。

没有保存每次优化更新前后的全部权重、全量原始梯度、Adam一阶二阶矩或完整激活。不能事后声称这些已存在；阶段快照只能重算固定探针的阶段梯度，不能还原历史训练时每一步的dropout和梯度。

## 现在可离线做的参数分析

`analysis/onevision_parameter_audit.py`在CPU读取完整保存文件，核验48模块／540672参数、有限值和SHA；分析各层A/B范数、实际deltaW相对baseW变化、奇异谱／95%能量秩、跨域deltaW余弦、输入／输出子空间典型相关、相邻顺序阶段的真实deltaW差及其方向；同时核验loss／梯度／有效学习率轨迹。LoRA分解不唯一，不能只对A/B逐元素相似度作机制结论。

连接已恢复；该只读CPU脚本已部署，并通过子空间不变性／正交性和deltaW差分数值检查，完成24份快照审计，结果在summary/onevision_diagnostics_20261016/parameter_audit.json。活动runner和冻结采样不变。后续随阶段快照增加重新执行。输入子空间重合还需控制所有独立适配器共享A初始化这一混杂，不能直接解释为语义冗余。

## GPU1空闲后的梯度重计算

使用相同版本／阶段A/B／冻结基座和事前固定TRAIN探针，显式eval模式禁用dropout，按每域最多16条重计算。保存参数名顺序、探针ID、逐层A/B梯度均值／范数／方差、跨域余弦、裁剪前后方向与均值原始张量，注明这是离线探针梯度而非历史逐步梯度。先与保存的NLL和参数SHA核对，重计算不能更新模型。

## 必须区分的解释

| 观察 | 应增加的对照 | 不能直接声称 |
|---|---|---|
| 测试低分 | train/test NLL、统一输出格式、问题语言、视觉消融、单任务独立控制 | 专业知识不足 |
| 训练也拟合差 | 有效学习率／更新大小、预算和rank对照、少样本记忆诊断 | 持续学习遗忘 |
| train改善而test变差 | 训练ID重复／答案分布、参数增幅、预算／正则对照 | 大模型一定更好 |
| 独立学会但顺序变差 | 严格匹配预算的逐任务控制、旧题损失、梯度和deltaW方向 | 所有退化均由梯度冲突引起 |
| LoRA子空间重合 | 真实跨域迁移、共享格式控制、只选已学LoRA的train-only路由 | 可以无损合并／减少容量 |
| 两样本梯度为负 | 扩大固定TRAIN探针、逐层分布、梯度干预对照 | 已证明因果干扰 |

路由、容量和超参数不按诊断测试答案选优；最终候选完整测试21454QA确认。研究报告要同时记录反例、无提升和适用范围。
