**端侧需存多少适配权重？** 按当前全量配置的未合并 FP32 张量计，共享 q/v LoRA 与八专家 CL-MoE 在 OneVision 上分别新增 **2.16／148.64 MB**，在 Qwen 上分别新增 **4.36／311.72 MB**。两个基座上，路由器均只占八专家新增权重的约 5.2%–5.3%。主要开销来自 LoRA 同时覆盖七类投影，并将每层总秩从 8 提高到 64。OneVision 保持七类投影和总秩 64，将架构从八个秩 8 专家改为一个秩 64 专家，LoRA 因子仍占 140.77 MB，总量降至 141.75 MB，仅少 4.63%。这里按十进制 MB 统计新增模型参数，任务统计和文件封装另计。[逐投影层字节核算](summary/image_disjoint_adapter_bytes_20261119/ADAPTER_BYTES.json)

**全量训练的同题耗时与显存。** OneVision 第一项任务的学习率预热共 64 次更新。相同的 1,024 道训练题上，共享 LoRA 用时 **12.08 分钟**，八专家用时 **73.72 分钟**，前者少用 **83.6%**。同一预热段，框架实际分配的 GPU 显存峰值分别为 **2.51／7.33 GB**；第 64 步结束时分别为 **1.87／2.46 GB**。逐步核对了输入与答案 token 数；两次运行在同机不同 RTX 2080 Ti 上，并发负载未控制。此处只计预热段的主训练更新。[配对计时](summary/image_disjoint_adapter_bytes_20261119/WARMUP_TIME.json)

**全量持续学习的阶段末开销。** 八专家 CL-MoE 在 19 个任务结束时统计路由权重，按全量训练清单合计需要 **129,460 次图文前向**。检索历史任务还需 **57,264–59,409 次纯文本前向**，具体次数取决于每个阶段开始统计时缓存了哪些题干。共享 LoRA 省去这两项开销。两种前向的耗时不同，完整训练用时待实测。

## 已有实验证据

端侧部署关注新任务需要增加多少权重、更新这些权重要花多少训练时间，以及序列结束后仍能回答多少旧题。下列数据来自原划分上已完成的低预算实验。动态收益指冻结同一模型后，按输入组合专家相对每层使用固定专家权重的 F1 差值。正式五域对照的固定权重取自训练题上的平均路由，专项实验另注明参照。

| 问题 | 观测与证据 |
|---|---|
| 少参数是否实际节省训练时间？ | 在同一主机、同型号 GPU 上逐步对齐训练题数和输入／答案词元数，共享 LoRA／CL-MoE 完成主训练更新的累计分钟数为 **12.0／75.2**（OneVision，1%）、**11.7／61.1**（Qwen，1%）、**113.8／537.7**（Qwen，10%）。共享 LoRA 少用 79%–84% 的主更新耗时，三组末态宏 F1 相对 CL-MoE 分别为 −0.588、+0.901、−0.866 点。计时不含评估、存盘和阶段末统计，并发负载未经控制。[逐阶段计时与全量源码核对](summary/parameter_efficiency_retention_20261118/PAIRED_TRAIN_UPDATE_TIME.json) |
| 按输入选择专家能多答对多少？ | OneVision CL-MoE 在完整 21,454 题上，1% 训练的动态／固定宏 F1 为 **42.774／42.689**，19,998 题同分、810 题动态更好、646 题固定更好。10% 为 **48.411／47.664**。预算提高后，动态收益增加 **0.662 点**，配对 95% 区间 [0.387, 0.940]。改按任务等权或整答匹配，1% 净差均不足 0.1 点，10% 均为正。1% PASs-MoE 为 46.620／46.332，其固定化同时改变了折叠和数值精度。[五域配对](summary/pct10_dynamic_fixed_20261116/BUDGET_PAIRED_UNCERTAINTY.json) · [评分复核](summary/routing_question_coverage_20261118/METRIC_READOUT.json) |
